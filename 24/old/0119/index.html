0119、安全开发篇（三）：构造析构与对象特性

发表于2026-07-07|更新于2026-07-07|网络安全Ferry学院安全开发
|字数总计:1.3k|阅读时长:4分钟|阅读量:

返回：C++ 面向对象基础目录 · 安全开发总目录

构造析构是 C++ 对象生命周期的核心。对象什么时候出生、资源什么时候拿到、什么时候释放、复制时是深拷贝还是浅拷贝，这些都直接影响稳定性和安全性。

4.4 默认构造函数

默认构造函数用于创建对象时不传参数。

4.5 带参构造函数

带参构造可以在对象创建时建立有效状态。

explicit 可以避免一些隐式转换带来的误用。

4.6 拷贝构造函数

拷贝构造在用一个对象初始化另一个对象时触发。如果类里有堆资源，默认浅拷贝可能出问题。

4.7 构造函数重载

同一个类可以有多个构造函数，根据参数不同建立对象。

4.8 委托构造函数

一个构造函数可以委托给另一个构造函数，减少重复初始化逻辑。

4.9 初始化列表

初始化列表比在构造函数体里赋值更早发生。const 成员、引用成员、没有默认构造函数的成员必须用初始化列表。

5.0 构造默认参数

构造函数也可以有默认参数，但不要让多个构造函数产生二义性。

5.1 构造函数删除

= delete 可以禁用某些构造或拷贝行为。

5.2 析构函数机制

析构函数在对象生命周期结束时自动调用，用来释放资源。

5.3 构造析构顺序

构造顺序通常是：基类 → 成员对象 → 当前类构造函数体。析构顺序相反。局部对象离开作用域时自动析构。

5.4 析构出场时机

对象类型 析构时机
局部对象 离开作用域
堆对象 delete 时
全局对象 程序结束时
静态局部对象 程序结束时

5.5 浅拷贝与深拷贝

浅拷贝只复制指针值，两个对象会指向同一块资源；深拷贝会复制资源内容。

复盘重点：只要类管理资源，就要考虑拷贝构造、赋值运算和析构。

5.6 静态成员变量

静态成员属于类，不属于某个对象。它在所有对象之间共享。

5.7 静态成员函数

静态成员函数没有 this 指针，只能直接访问静态成员。

5.8 常量成员变量

const 成员必须在初始化列表中初始化。

5.9 常量成员函数

const 成员函数承诺不修改对象状态。

6.0 常量对象特性

常量对象只能调用常量成员函数。这样能保证只读对象不被修改。

6.1 对象调用规则

普通对象调用成员函数时会隐式传入 this 指针。const 对象的 this 类型不同，所以只能调用 const 成员函数。

6.2 对象指针本质

对象指针保存对象首地址。成员变量通过偏移访问，成员函数通过代码地址调用。

6.3 对象指针特性

对象指针要关注空指针、生命周期和真实动态类型。继承多态后，基类指针可能指向派生类对象。

6.4 类的友元函数

友元函数可以访问类的私有成员，但会破坏封装边界。只在确实需要时使用。

6.5 友元函数与类

友元类会获得更大访问权限，项目中要谨慎使用，避免对象内部状态被随意修改。

静态成员 是否引入共享状态

友元 是否真的需要突破封装
