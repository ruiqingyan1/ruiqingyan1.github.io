0102、安全开发篇（一）：VS配置 和 基础框架

发表于2026-07-06|更新于2026-07-08|网络安全Ferry学院安全开发

这一节先把开发环境和最小程序框架跑通。后面学习变量、数组、指针、函数栈、PE 和逆向分析时，所有实验都会回到同一个问题：代码如何被写出来、编译出来、运行起来。

1.0 前言：课程体系与学习路线

安全开发可以先按三层理解：

层次 内容 作用
语言基础 C 语言、C++ 基础、指针、结构体、函数、文件、内存 能写小程序，也能读懂后续示例代码
系统基础 Windows 程序、API、编译链接、调试、进程和内存 能理解程序如何在系统上运行
安全连接 逆向分析、漏洞成因、内存边界、注入和防护思路 把开发能力转成安全分析能力

本课程前期看起来很基础，但不要跳太快。后面的缓冲区、指针、函数栈、PE、ShellCode 和逆向分析，都会默认你已经理解“程序如何组织”和“代码如何运行”。

本章目标可以压缩成四句话：

  1. 能安装并打开 Visual Studio。
  2. 能创建 C/C++ 控制台项目。
  3. 能添加 .c 或 .cpp 源文件并写出最小程序。
  4. 能运行、调试，并观察最小程序的执行结果。

1.1 Visual Studio 安装与配置

本课程使用 Visual Studio 作为主要实验环境。它既能写 C/C++，也能编译、调试、看调用栈和反汇编，比较适合安全开发和逆向入门阶段。

代码能编译只是第一步，能观察它如何运行才是学习安全开发的关键。

1.5 注释方式

注释的作用是方便自己和他人阅读代码。注释内容不参与编译，也不会影响程序执行结果。

注释不应该重复代码表面意思，而应该解释“为什么这样写”。

注释方式 适合场景
单行注释 解释一行代码、一个变量、一个关键判断
多行注释 解释一段逻辑、函数目的、实验结论
行尾注释 简短补充，不要写太长

1.6 #include 预处理指令

#include 是预处理指令，不是普通 C 语句，所以结尾不需要分号。

尖括号和双引号

写法 常见用途
#include <xxx.h> 优先从系统头文件目录查找
#include "xxx.h" 优先从当前工程或当前文件所在目录查找，找不到再查系统目录

例如：

预处理的理解方式

可以先粗略理解为：

  1. 编译前，预处理器先扫描 # 开头的指令。
  2. 遇到 #include，把对应头文件内容纳入当前编译单元。
  3. 之后编译器再正式分析 C 语法。

后面写多文件项目时，头文件会承担函数声明、结构体声明、宏定义和公共接口描述等作用。

1.7 函数调用过程

函数可以把一段逻辑封装起来，让程序结构更清楚。

调用流程

步骤 说明
1 程序从 main 开始
2 执行到 print_banner();，跳到 print_banner 函数
3 print_banner 执行完，返回 main
4 执行到 add(3, 5)，把参数传给 add
5 add 返回计算结果
6 main 输出结果并结束

函数声明、定义和调用

概念 含义
声明 告诉编译器有这个函数，参数和返回值长什么样
定义 函数真正的实现代码
调用 在某个位置使用这个函数

后面学函数栈、调用约定、返回地址、栈溢出时，都会用到函数调用过程。现在先建立一个直觉：

  1. 调用函数时，程序执行流会临时跳到另一个函数。
  2. 函数执行完后，要回到调用位置继续执行。
  3. 参数和返回值是调用者与被调用者之间的数据交换方式。

1.8 控制台指令和命令行参数

控制台程序适合初学，因为输入输出直接、运行结果清楚。

指令 说明

cd 切换目录
dir 查看当前目录文件
.\demo.exe 在当前目录运行程序

命令行参数预告

命令行参数后续做工具类程序会很常见，比如指定文件路径、IP、端口、扫描目标或配置项。

1.9 语法规范风格

代码风格不影响程序能不能编译，但会影响能不能长期维护。

项目 建议
缩进 同一项目统一 4 空格或 Tab，不混用
命名 变量名表达含义，不用 a1、tmp2 到处乱飞
括号 {} 风格统一，嵌套层级清楚
空行 用空行分隔逻辑块，不要整篇挤在一起
注释 解释原因、边界和坑点，不重复代码表面意思
